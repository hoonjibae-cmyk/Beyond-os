# 알림톡 템플릿 등록 안내 — 비욘드 좌석번호 및 닉네임 안내 (v41-271)

매 기수 시작 전에 수강생 보호자에게 좌석번호와 닉네임을 개별로 안내하는 템플릿입니다.
Beyond OS 설정 › 공지사항 발송 › 유형 **[좌석번호·닉네임 안내]** 에서 보냅니다.

## 1. SOLAPI 템플릿 등록 값

| 항목 | 입력값 |
|---|---|
| 채널 | 목동유쌤영어학원 발신프로필 (기존 템플릿과 동일) |
| 템플릿 이름 | `비욘드 좌석번호 및 닉네임 안내` (포괄적인 "공지"·"안내" 단독 이름은 반려 사유) |
| 카테고리 | **서비스이용 › 이용안내/공지** (1순위). 콘솔에 대분류만 보이면 **서비스이용**. "기타"는 심사가 길어지므로 피함 |
| 메시지 유형 | 기본형 |
| 강조 유형 | 선택 안 함 (기존 승인 템플릿과 동일. 강조표기형을 쓰려면 강조문구 `좌석번호 및 닉네임 안내`, 보조문구 `비욘드 학기 중 프로그램`) |
| 보안 템플릿 | OFF |
| 버튼 | 없음 |
| 변수 | `#{학생이름}` `#{좌석번호}` `#{닉네임}` — 검수 요청 시 변수 예시값 필수 입력: 김민준 / 26번 / 야무짐 |
| 본문 길이 | 643자 (변수 포함, 한도 1,000자) |

카테고리 근거: 카카오 검수 가이드 화이트리스트의 "구매완료 상품(서비스)에 대한 사용법 안내"와 "학교/학원/e러닝 학사일정 안내" 항목에 해당합니다. 수강 등록이라는 계약 관계에 따른 이용 안내이므로 서비스이용 대분류가 맞습니다.

### 본문 (그대로 복사)

```
[The Place 26 · 비욘드 학습관리센터]
비욘드 좌석번호 및 닉네임 안내

안녕하세요, 학부모님.
비욘드 학기 중 프로그램에 수강 등록하신 #{학생이름} 학생의 좌석번호와 닉네임을 안내드립니다.

[개별 안내]
▶ 학생 이름: #{학생이름}
▶ 좌석번호: #{좌석번호}
▶ 닉네임: #{닉네임}

[닉네임 안내]
닉네임은 프로그램 기간 중 순공시간 랭킹을 공개할 때만 사용됩니다.
타인에게 공개하지 마시고 본인 닉네임을 꼭 기억해 주세요.
※ 닉네임 공개에 동의하지 않으신 경우 랭킹에는 닉네임 대신 ♥♥♥로 표기됩니다.

[태블릿 준비 안내]
인강 시청용 태블릿은 등원 전 반드시 정리해 주세요.
학습 관련 앱을 제외한 모든 앱(인스타그램, 카카오톡, 유튜브, 게임 등)은 삭제 부탁드립니다.
프로그램 기간 중에는 센터의 차단앱으로 비학습 앱 사용을 제한합니다.
다만 기술적인 차단만으로는 한계가 있습니다.
학습 환경을 지키는 가장 확실한 방법은 학생 본인의 자발적인 실천입니다.
가정에서도 함께 점검해 주시면 아이가 훨씬 수월하게 집중할 수 있습니다.

감사합니다.

※ 이 메시지는 비욘드 학기 중 프로그램에 수강 등록한 학생의 보호자께 발송되는 안내입니다.
문의: The Place 26 비욘드 학습관리센터 (031-795-3306)
```

### 변수에 들어가는 값 (Beyond OS가 자동으로 채움)

| 변수 | 값 | 예시 |
|---|---|---|
| `#{학생이름}` | 학생 정보의 이름 | 김민준 |
| `#{좌석번호}` | 학생 정보의 기본 좌석 + "번" | 26번 |
| `#{닉네임}` | 학생 정보의 닉네임. 랭킹 공개 미동의이고 닉네임이 없으면 "비공개 (랭킹에 ♥♥♥로 표기)" | 야무짐 |

### 심사 기준 검토 결과 (v41-271.1)

| 검토 항목 | 기준 | 결과 |
|---|---|---|
| 정보성 여부 | 수신자의 행동(수강 등록)에 따른 결과·이용 안내여야 함. 발신자 필요에 따른 간헐적 공지는 불가 | 충족. "수강 등록하신 … 학생의 좌석번호와 닉네임을 안내" + 발송 대상 명시 문장 추가 |
| 정형화 | 수신자 정보만 바뀌고 같은 조건에서 같은 내용이 나가야 함 | 충족. 변수 3개 외 고정 본문 |
| 광고성 요소 | 혜택·할인·재등록 유도·친구추가 유도·앱 설치 유도 금지 | 없음 |
| 템플릿 이름 | 포괄적 이름("공지", "안내") 반려 | 구체적 이름 사용 |
| 변수 | 40개 이하, 변수만으로 구성 금지, 예시값 필수 | 3개, 고정 본문 위주, 예시값 지정 |
| 글자 수 | 본문 1,000자 이내 | 643자 |
| 특수문자 | 유니코드(BMP)에서 지원되는 문자만. 컬러 이모지 불가 | `·` `▶` `※` `♥` 모두 BMP 기호. 컬러 이모지 없음 |
| 발송 대상 | 계약 관계(교육기관-수강생)를 템플릿 안에 명시 | 첫 문장과 하단 안내 문장에 명시 |
| 학생 수신 | 본문이 "학부모님"으로 시작 | 학생에게도 같은 문구로 감. 학생용은 별도 템플릿 필요 |

위험 요소 1건: `♥` 기호는 유니코드 기본 영역 문자라 규정상 허용 범위이나, 검수자가 장식 기호로 볼 가능성이 0은 아닙니다. 반려되면 해당 문장을 "랭킹에는 닉네임 대신 하트 3개로 표기됩니다."로 바꿔 재등록하면 됩니다. (Beyond OS 쪽 닉네임 비공개 문구도 함께 바꿔야 하므로 그때 말씀해 주세요.)

## 2. 승인 후 Vercel 환경변수

| 이름 | 값 |
|---|---|
| `SOLAPI_TEMPLATE_ID_NOTICE_SEAT_NICKNAME` | 승인된 템플릿 ID |

환경변수를 넣고 재배포하면 공지사항 발송에서 이 유형이 실제로 나갑니다. 넣기 전에는 "SOLAPI 설정이 부족합니다" 로 멈춥니다.

## 3. 발송 전 점검 (Beyond OS)

1. 화면 상단 [기수 보기]에서 보낼 기수를 고릅니다. 그 기수 수강 명단에만 나갑니다.
2. 설정 › 학생 관리에서 수강생의 **기본 좌석**과 **닉네임**이 채워져 있는지 확인합니다. 닉네임은 [닉네임 일괄 배정]으로 한 번에 만들 수 있습니다.
3. 설정 › 공지사항 발송 › [좌석번호·닉네임 안내] 유형 → 제목(내부용, 예: "3기 좌석·닉네임 안내") 입력 → [공지 저장] → [발송 준비].
4. 확인창에 보낼 학생(좌석·닉네임)과 빠지는 학생(사유)이 나옵니다. 빠지는 학생은 정보를 채운 뒤 다시 [발송 준비]를 누르면 들어옵니다.
5. 테스트 수신번호 모드에서는 첫 학생의 값이 견본으로 테스트 번호에 갑니다. 실전 발송 전에 설정 › 리포트 발송 설정에서 테스트 모드를 끕니다.

## 4. 동작 규칙

- 보호자 기준: 활성 학생 · 데일리 리포트 수신 ON 보호자. 수신 대상을 [학생]/[둘 다]로 바꾸면 학생 본인 연락처에도 갑니다.
- 형제가 같은 기수에 있으면 보호자 한 번호로 학생 수만큼 각각 나갑니다. (내용이 다르므로 중복 허용)
- 보호자 번호와 학생 번호가 같으면 그 학생 건은 한 통만 갑니다.
- 발송 이력은 공지 목록의 [발송 대상]에서 "학생 · 보호자 · 번호(마스킹)" 로 남습니다.
